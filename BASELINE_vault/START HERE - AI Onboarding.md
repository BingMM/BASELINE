# START HERE - AI Onboarding

This Obsidian vault is versioned project memory for the `BASELINE` repository.
It is not the user's second brain, and it is not a substitute for inspecting
the live repository.

Codex should normally discover the repository workflow through
[`AGENTS.md`](<../AGENTS.md>). This note is the human and Obsidian entry point.

## Reading order

When asked to become current on the project:

1. Read [`AGENTS.md`](<../AGENTS.md>) if it is not already in context.
2. Read the [Project Brief](<01_Project/Project Brief.md>).
3. Read [Current State](<01_Project/Current State.md>).
4. Read [Handoff - Latest](<05_Handoff/Handoff - Latest.md>).
5. Read relevant entries in the [Decision Log](<03_Decisions/Decision Log.md>)
   or algorithm notes only when the task requires them.
6. Read dated files in [`04_Sessions`](04_Sessions/) only for historical
   investigation. Do not load the complete session archive by default.

After reading, report briefly:

- what the repository is trying to reproduce;
- which implementation track is active;
- the current validated state and next action;
- known blockers, risks, or unverified assumptions.

## Maintenance rules

Update the vault only when a session changes durable project understanding.
Summarize evidence and link to repository-relative code, tests, or figures.

Do not paste raw command output, duplicate the same narrative across notes, or
keep obsolete next steps in the live handoff. Use the conventions below for
ownership and closeout rules.
