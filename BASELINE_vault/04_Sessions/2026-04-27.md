## Durable Planning Decision

The repo should explicitly treat the future `baseline_v2` branch as a separate
track from the current SuperMAG-reproduction code.

Positioning:

- `main`: reference / paper-reproduction track
- `baseline_v2`: modernized track allowed to deviate scientifically when it
  improves robustness, accuracy, or speed

This is not framed as a cleanup of the current `BaselineEstimator`. It is
framed as a new engine with different design goals.

## Proposed V2 Architecture

The design doc recommends:

- a new `baseline_v2/` package rather than modifying `baseline/` in place;
- typed array containers such as `BaselineInputs`, `Step1CResult`, and
  `BaselineResult`;
- pandas at the boundaries only, not inside the hot numerical loops;
- a `ModernBaselineEngine.fit_component(...)` style orchestrator;
- a separate reference Step 1c path and robust Step 1c path.

## Proposed V2 Scientific Direction

Near-term V2 should first build an array-first compatibility path that
reproduces the current logic with cleaner internals and better runtime.

After that, the first real scientific change should be a new Step 1c estimator
based on a dominant contiguous quiet-time region rather than a single modal
bin plus one hard Gaussian-fit threshold.

The design doc also records a longer-term direction:

- treat Step 1c as a local observation model for a latent baseline rather than
  as the final estimator;
- eventually explore uncertainty-aware global smoothing or a latent-state
  model.

## Recommended Build Order

The documented V2 sequence is:

1. create `baseline_v2` package skeleton and typed containers;
2. implement an array-first compatibility engine;
3. freeze regression and benchmark datasets;
4. replace the Step 1c inner loop with incremental histogram accumulation;
5. add a robust dominant-region Step 1c estimator;
6. move toward uncertainty-aware smoothing;
7. optionally prototype a state-space version later.

## Later Same-Day Implementation - First Experimental Robust Step 1c Path

The first actual modern V2 algorithmic deviation is now implemented.

Files:

- `baseline_v2/step1c_robust.py`
- dominant-region estimator added in `baseline_v2/reference_math.py`

Behavior:

- `ModernBaselineEngine(... step_1c_method=\"robust\")` now runs a real
  alternative Step 1c estimator;
- it identifies a dominant contiguous histogram region around the modal peak;
- it estimates center/spread from that region instead of fitting the full
  histogram blindly;
- it can reject ambiguous balanced bimodal windows by returning an invalid
  spread and forcing window expansion.

Current scope note:

- only the Step 1c local estimator changes between `reference` and `robust`;
- the surrounding Step 1d / Step 2 pipeline is still shared.
