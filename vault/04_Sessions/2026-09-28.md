# 2026-09-28 Coordinate-Rotation Fix

## Problem

For absolute horizontal components near X=7500 nT and Y=3000 nT,
`CoordinateRotator` returned an effectively unchanged X/Y pair. Removing the
large component levels made a rotation visible, although those absolute levels
are required to determine the instrument's orientation relative to magnetic
north.

## Cause

`q_raw = unwrap(arctan2(Y, X))` is measured in radians, but the class passed it
to the baseline typical-value estimator with its default fixed `1.0` bin width.
That default represents `1 nT` for field components. Applied to radians, it
became a 57.3-degree bin: the expected 21.8-degree declination fell in the bin
centered on zero, so smoothing and interpolation preserved `q=0` and the final
rotation became an identity.

## Fix

- Added an explicit `bin_width` option to
  `baseline/baseline_estimator.py::get_typical_value` while preserving its
  `1 nT` default.
- Added configurable `declination_bin_width_degrees=0.1` to
  `baseline/coordinate_rotator.py` and converted that width to radians at the
  call site.
- Added `tests/test_coordinate_rotator.py` covering the reported absolute-field
  geometry and invalid bin widths.
- Documented the separate field and angular histogram resolutions.

## Verification

- Confirmed: the regression recovers approximately 21.8 degrees and reduces
  the rotated mean E component from roughly 3000 nT to near zero.
- Confirmed: all 16 focused unit tests pass.
- Confirmed: the broad Python syntax check passes.
- Confirmed on all 525,600 samples of `data/DMH_1min_2025.csv`: median
  declination is -12.77 degrees. In the first seven days plotted by the real
  data example, mean Y changes from -1654.7 nT to a rotated E mean of 1.0 nT.
- Regenerated and visually inspected `figures/real_rotation.png` using the
  original script's loading, rotation, and plotting path.
- Not run: the downstream variance and baseline-estimation stages, which are
  unrelated to producing the rotation figure.
